# GOTCHAS — pitfalls & sensitive areas

## 1. FODOL security boundary (highest risk)
- The protection design (see header comments in `src/lib/contentApi.ts` lines 1–24 and `ProtectedPage.tsx` lines 1–18) rests on: client never builds page URLs; grants are opaque, 60s, single-use per page; concurrency bounded; everything else enforced server-side.
- **Do not** add URL templates for content, batch/pre-cache grants, store tokens in localStorage/sessionStorage, raise concurrency, or copy the API base into any other module.
- Client-side "protections" (context menu, select, print, keyboard) are explicitly **friction, not security** — do not present them as protective and do not remove the honest documentation.
- The session cookie is HttpOnly — any change assuming the client can read it is wrong.

## 2. Dual-locale / RTL is a first-class constraint
- Every string ships twice (`t(ar,en)` / `_ar`+`_en` fields). A "trivial" text edit that skips one language breaks `/en` or `/ar`.
- Layout must work RTL (`/ar`, default) and LTR (`/en`); Navbar/Footer and all views are affected. Test 320px → 1440px.

## 3. Two base paths coexist
- GitHub Pages serves under `/scii/` (`base` set when `GITHUB_ACTIONS=true` in vite.config.ts); Vercel/Cloudflare under `/`.
- Any new hard-coded `/assets`, `/images` path silently breaks one host. Use `publicAsset()` / `%BASE_URL%`.

## 4. No real test suite
- `npm test` = build + `scripts/verify-release.js` (static artifact checks: dist files, brand hexes in compiled CSS, bundle spot-checks). Passing ≠ feature works.
- The brand hex list is duplicated in that script — CSS token changes must update it or the release gate fails spuriously.

## 5. Outdated/conflicting docs (trust order: package.json > vite.config.ts > this doc > DEPLOYMENT.md)
- `DEPLOYMENT.md` references an old path (`d:\mo\frontend`), stale Node version, and Supabase env vars that may not reflect current code.
- `package.json` name is `frontend`; the site is "Sci Infinity (FODOL)".
- `.env.example` documents `VITE_DB_MODE` / `VITE_ENABLE_LIVE_FORMS` / Supabase vars — **none of these strings appear anywhere in `src/` or `scripts/`** (verified by grep). Likely dead config from an earlier version. Needs confirmation with the maintainer before anyone wires them in.
- `pdfjs-dist` is in dependencies but the code loads pdf.js from a CDN at runtime (`PdfThumbnail.tsx`, `AnnualForumView.tsx`). Needs confirmation why both exist.
- `vite-plugin-pwa` is a devDependency but **not referenced in vite.config.ts** — PWA files (sw.js, manifest.json, offline.html) are hand-maintained in `public/`. Don't assume plugin-generated PWA behavior.

## 6. Content pipeline is external
- `public/magazine/fudul-issue-1/**` webp images and `src/data/fbUrlMapping.json` are generated by server-side tooling / scripts (`scripts/*.py`, `fix_poster_paths.mjs`, `convert_posters.py`). Regenerate, don't hand-edit.
- `private-storage/` (original PDFs, watermark DB) is git-ignored for a security reason — **never** copy, import, or commit from it.

## 7. Intentional oddities (do not "fix")
- `TeamView` is imported/commented out on purpose — preserved for future use; `/team` redirects home.
- `src/data/seedDataUpdated.json` sits next to `seedData.ts` — migration artifact, not the live source.
- `AnnualForumView.tsx` contains a pdfjs canvas poster viewer with `/* @vite-ignore */` CDN import — deliberate, keep it out of the bundle.

## 8. Sensitive areas quick list
`src/lib/contentApi.ts`, `src/components/reader/ProtectedPage.tsx`, `src/index.css` (release-verified tokens), `scripts/verify-release.js`, `.github/workflows/deploy.yml`, `vercel.json`, `.gitignore` (private-storage rule). Changes here: show the maintainer before committing.
