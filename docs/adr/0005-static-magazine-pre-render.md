# ADR 0005 — Static magazine pre-rendered to WebP, served from `public/`

**Status:** Accepted — the FODOL protected reader (ADR 0001) coexists as a **second**, grant-based
path for the *same* magazine. · **Date:** 2026 (pre-dates this documentation) · **Code:**
`src/views/MagazineView.tsx`, `public/magazine/fudul-issue-1/`

## Context

The site ships **two readers for the FODOL magazine**:

1. **Static** (`MagazineView`) — pre-rendered WebP pages shipped as ordinary files under
   `public/magazine/fudul-issue-1/{desktop,mobile}/pNNN.webp`. Fast, offline-friendly, zero server
   dependency, but **unprotected** — anyone can list the paths.
2. **Protected** (`reader/ProtectedPage.tsx`) — grant-gated delivery from the external FODOL server
   (see ADR 0001).

The two are not a contradiction; they are a trade-off for different content sensitivity. Static
delivery is for material that may be public; protected delivery is for the controlled FODOL issue.

## Decision

- Static pages are **pre-rendered server-side** (the FODOL ingest pipeline: `FODOL_MUTOOL_PATH` for
  PDF→image via mutool, `FODOL_IMAGE_TOOL`/ImageMagick for watermarking + WebP, max render
  40 000 000 px — all documented in `.env.fodol.example`). The tooling and the pipeline run in the
  **server repository and `.tools/`** (git-ignored here); this repo only ships the output.
- Assets are organized as `public/magazine/<issue-slug>/{desktop,mobile}/pNNN.webp`; the client
  picks the variant by breakpoint via `chooseVariant(widthPx)` (`<768` mobile, `<1280` tablet,
  else desktop) — the same breakpoint constants reused by the protected side, keeping both readers
  coherent.
- `public/magazine/**` is **generated content**: AGENTS.md forbids editing it by hand; it is
  regenerated by the server-side pipeline. `.gitignore` does not exclude it (it is committed as
  static output), so treat diffs there as *content redeploy*, not code changes.

## Evidence
- `MagazineView.tsx` — one of the largest views (~680 L), reads the pre-rendered WebP set; the
  `public/magazine/fudul-issue-1/{desktop,mobile}/` tree ships ~39 pages per variant — VERIFIED by
  directory listing.
- `.env.fodol.example` (139 L) — ingest tooling variables and render limits — VERIFIED (full read).
- `contentApi.ts#chooseVariant` — shared breakpoint logic — VERIFIED.

## Consequences

- **Never** commit originals, PDFs, or watermark keys into this repo's `public/` — that would defeat
  the protection model (see `SECURITY.md`).
- Releasing a new issue = run ingest on the server, copy the rendered WebP tree into
  `public/magazine/<new-slug>/`, update the issue metadata in `seedData.ts` (or add a new
  `MagazineIssue` record), and ship. No client change is needed for a new issue of the same shape.
- The static reader is a **fallback + public** path; the protected reader is the **controlled**
  path. Do not merge them; each serves a different trust model.
